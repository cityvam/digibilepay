# DigiBilePay

سامانهٔ مدیریت خدمات مالی، درخواست‌های تسهیلات و پرداخت دیجیتال.

## شاخهٔ مرجع

- شاخهٔ مرجع توسعه و بررسی: `main`
- همهٔ تغییرات قابل انتشار باید ابتدا در `main` بررسی و آزمایش شوند.
- شاخه‌های `feat/*` و `fix/*` باقی‌مانده، شاخه‌های کاری/تاریخی‌اند؛ آن‌ها را برای استقرار انتخاب نکنید. حذف آن‌ها بدون بررسی و نگهداری سابقه انجام نمی‌شود.

## اجرای پیش‌نمایش توسعه در Codespaces

این پیش‌نمایش از SQLite محلی استفاده می‌کند و به دیتابیس عملیاتی وصل نمی‌شود.

```bash
python3 backend/dev-preview-server.py --host 0.0.0.0 --port 8080
```

سپس پورت 8080 را در بخش Ports روی حالت قابل مشاهده قرار دهید و آدرس آن را باز کنید.

دستورهای کمکی:

```bash
python3 backend/dev-preview-server.py --check-db
python3 backend/dev-preview-server.py --create-user
python3 backend/dev-preview-server.py --set-role
```

در پیش‌نمایش توسعه، OTP ثابت `123456` است و پیامک واقعی، استعلام بانکی، OCR و انتقال وجه واقعی انجام نمی‌شود. این پیش‌نمایش برای دادهٔ واقعی مشتری یا استقرار عمومی مناسب نیست.

## آزمون‌ها

با سرور پیش‌نمایش در حال اجرا، در ترمینال دوم:

```bash
export DIGIBILEPAY_DATA_DIR="$PWD/.test-data/digibilepay-test-data"
python3 tests/check_preview.py
```

گردش‌کار GitHub Actions در مسیر `.github/workflows/dev-preview-tests.yml` بررسی نحوی Python، اسکریپت‌های JavaScript در صفحات HTML و آزمون‌های API پیش‌نمایش را اجرا می‌کند. تا زمانی که اجرای موفق CI روی commit جاری ثبت نشده باشد، نتیجهٔ آزمون را موفق فرض نکنید.

## وضعیت آمادگی برای تولید

**این مخزن در وضعیت فعلی به‌تنهایی بستهٔ قابل استقرار نهایی نیست.** موارد زیر پیش از استقرار عملیاتی باید تکمیل و با شواهد آزمون تأیید شوند:

1. پروژهٔ پایهٔ ASP.NET مورد انتظار نصب‌کننده‌ها (از جمله `src/Ghestine.API` و `src/Ghestine.Infrastructure`) در این مخزن موجود نیست؛ اسکریپت‌های نصب به پروژهٔ پایهٔ بیرونی وابسته‌اند.
2. پشتهٔ نهایی معرفی‌شده در مستندات، یعنی Next.js، در شاخهٔ `main` فایل اجرایی `web-next/package.json` ندارد؛ بنابراین دستورهای build مربوط به Next.js در این مخزن قابل اجرا نیستند.
3. اسکریپت‌های نصب فعلی مسیرهای پیش‌فرض قدیمی با نام دامنه/پروژهٔ دیگری دارند. بدون تعیین مسیر واقعی پروژه و بازبینی اسکریپت‌ها آن‌ها را اجرا نکنید.
4. اسکریپت‌های بازیابی و مهاجرت دیتابیس باید ابتدا روی نسخهٔ کپی‌شده و قابل دورریختن از دیتابیس آزمایش شوند؛ روی دیتابیس اصلی اجرا نشوند.
5. پیش‌نمایش SQLite، OTP توسعه‌ای و داده‌های نمایشی را با سرویس‌های عملیاتی، درگاه پرداخت، پیامک یا اطلاعات مشتریان واقعی اشتباه نگیرید.
6. فایل‌های بکاپ، dumpهای واقعی، رمزها، کلیدهای درگاه و اطلاعات هویتی نباید وارد Git شوند.

## مستندات

- `README-DigitalPay.txt`: معماری بسته، ماژول‌ها و محدودیت‌های شناخته‌شده.
- `README-DB-fa.md`: یادداشت‌های استخراج و مهاجرت داده؛ فرض‌ها و موارد تأییدنشده را قبل از هر مهاجرت بخوانید.
- `backend/DEV-PREVIEW.txt`: راه‌اندازی و محدودیت‌های پیش‌نمایش Codespaces.

## اصل استقرار ایمن

استقرار فقط پس از تکمیل پروژهٔ پایه، تعیین مسیر صحیح، تأیید نسخه و نوع دیتابیس، تهیهٔ بکاپ قابل‌بازیابی، موفقیت build/test و اجرای آزمایشی روی staging مجاز است. هیچ‌یک از مراحل بالا با صرف وجود فایل‌های نصب یا مستندات، انجام‌شده محسوب نمی‌شود.
